# BDD、DDD 與 AI 驅動開發討論摘要

**日期：** 2026年5月15日，星期五

## 1. 核心概念總結

### 行為驅動開發 (BDD)
*   **來源：** 《BDD in Action》
*   **目標：** 透過確保「做正確的事」與「把事做正確」，開發出能發揮價值的軟體。
*   **關鍵實踐：** 透過結構化的對話與具體範例進行協作探索。
*   **可執行規格：** 使用 Gherkin 語法 (`Given-When-Then`) 將需求轉化為自動化驗收測試，同時作為「活文件」。

### 領域驅動設計 (DDD)
*   **來源：** 《Learning Domain-Driven Design》
*   **目標：** 解決因溝通隔閡與業務複雜性引起的「軟體危機」。
*   **策略設計：** 分析業務領域、定義「限界上下文 (Bounded Context)」，並建立「通用語言 (Ubiquitous Language)」。
*   **戰術設計：** 使用「聚合 (Aggregate)」、「實體 (Entity)」與「數值物件 (Value Object)」等模式實作領域模型，使程式碼與業務邏輯對齊。

## 2. 比較：BDD vs. DDD

| 特性 | BDD (行為驅動) | DDD (領域驅動) |
| :--- | :--- | :--- |
| **焦點** | 系統行為 | 領域模型與結構 |
| **問題** | 「當...時應該發生什麼？」 | 「核心業務邏輯是什麼？」 |
| **主要工具** | 可執行的範例 (Gherkin) | 通用語言與限界上下文 |
| **視角** | 由外而內 (使用者/功能導向) | 由內而外 (業務邏輯/模型導向) |
| **協作** | BDD 驗證業務價值 | DDD 處理內部複雜性 |

## 3. 願景：利用 AI Agent 實現自動化軟體工程

目標是將 DDD、BDD 與 TDD 結合，為 AI Agent 建立自動化流水線：

1.  **DDD 確立架構：** 定義限界上下文與通用語言，為 AI 提供清晰的「地圖」與一致的詞彙，防止產生混亂的架構。
2.  **BDD 確立規格：** 將 Gherkin 情境作為高精確度的 AI 提示詞 (Prompt)，定義 AI 需要達成的目標。
3.  **TDD 建立回饋循環：**
    *   AI 根據 BDD 規格生成單元/驗收測試。
    *   AI 嘗試實作程式碼 (Red -> Green)。
    *   AI 根據 DDD 原則進行重構 (Green -> Refactor)。
4.  **結果：** 自動生成高品質、模組化且具備自我文件化的軟體框架，人類只需最少程度地干預實作細節。
